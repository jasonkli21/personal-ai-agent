# Phase 20 — private immutable artifact tier

The phase-local implementation puts compressed immutable bodies behind one internal `ArtifactService`. Postgres migration **019** owns compact references, lifecycle revisions, conservative storage budgets and owner deletion fences. GCS owns bodies and exact generations. Memory vectors, conversations, domain records and quota controls keep their existing stores. DynamoDB receives no artifact body or metadata mirror; its existing bounded actual-build inspector manifests remain unchanged.

## Contracts and adapters

- `personal_ai.artifacts.contracts`: `ArtifactStore`, `ArtifactRef`, `ArtifactMetadataRepository`, typed lifecycle failures and immutable transition checks. References contain owner/application/workspace, run identity, optional routing/invocation/evaluation/cascade IDs, store/bucket identity, service-generated key, generation, two hashes, compression/content/schema, sensitivity, grant dependencies, expiry, state and numeric summaries. Scope determines the hashed object prefix. Clients cannot choose keys.
- `artifacts.local`: deterministic in-memory object and metadata adapters with locks, CAS, generation preconditions, and stock/flow guards. The runtime's memory body store is local/test only and uses canonical Postgres metadata; restarting loses fake bodies and reconciliation reports them unavailable. It is not durable storage evidence.
- `artifacts.gcs`: bounded HTTPX JSON API with workload ADC, fixed Google endpoint, no redirects/retries, generation-zero creation, exact-generation reads/deletes and duplicate-body validation. It requires private bucket verification before IO. Credentials never enter metadata, exports or logs.
- `artifacts.service`: bounded deterministic gzip JSON/JSONL encoding, compressed/raw hash and size validation, authorization before and after IO, optional advisory failure, required ready exports, reconciliation and retention. Context traces, routing candidates, evaluation batches and debug observations use positive typed, bounded retention contracts; arbitrary text-bearing mappings are not accepted.
- `persistence.postgres_artifacts`: compact metadata, indexed scope/run joins, atomic global budgets and owner fences. Body content never enters its payload. Lifecycle updates preserve immutable facts and compare revisions.

Bodies are limited to **8 MiB uncompressed / 1 MiB compressed**; references to **8 KiB**. Retention is explicitly bounded to **90 days**, shortened by source-rights/dependency expiry. Default context/debug retention is seven days, evaluation retention thirty days and export retention one day. Numeric summaries and bounded metadata are queryable in Postgres. Routing observations admit only typed candidate identifiers, codes, and numeric facts. Evaluation/debug bodies retain only bounded identifiers, outcome labels, and numeric facts; vector-shaped numeric lists are rejected. Context traces use the content-free manifest contract and safe-token values. These internal consumers cannot pass arbitrary text-bearing mappings through a field-name denylist.

## Recovery and retention

Flow-budget admission and creation of the `pending` reference commit atomically before upload; rejected writes leave no live metadata. Generation/hash readiness is published with CAS. Upload retries use the same immutable body/key. Transient publication failure preserves the pending object for recovery. Identical concurrent publications reuse the ready generation. Missing or corrupt reads are unavailable, never successful partial reads. `missing` objects may recover only after exact hash/decompression validation; corrupt tracked bodies are deleted using their generation. Delete records `deleting` before object deletion and records `deleted` after acknowledgment; missing objects are idempotent deletions. A failed generation precondition cannot delete a replacement.

`reconcile(limit=1..100)` rotates bounded batches, prioritizes expiry/deletion/fenced owners, recovers uploaded pending bodies, and removes expired/revoked objects. It does not re-download healthy immutable `ready` bodies; reads and exports verify their hashes and decompression, while pending/missing recovery validates before publishing `ready`. Pending objects absent after ten minutes become `missing`. Uploads start only within one minute of reference creation, and each GCS request has a ten-second deadline. Recent tombstones are checked for ten minutes to reclaim an upload/delete race by verifying the original body at the discovered generation. The configured store cannot change while live references or recent tombstones point to another store; reference creation enforces this in the same transaction as global admission, including across concurrently running application instances. To rotate buckets, restore the old store configuration, drain references and the ten-minute tombstone window, then change the configuration. No arbitrary bucket-wide listing or orphan-key deletion is permitted: every upload has a canonical reference before IO. Metadata tombstones are retained; full physical account record removal remains the Phase 9 operator workflow.

Expiry denies retrieval immediately even when physical deletion is delayed or a budget/outage defers cleanup. Scheduled maintenance invokes bounded reconciliation before requiring an active owner, so deleted owners' bodies can be cleaned. Its internal response includes reference/body byte estimates, lifecycle counts and reserved IO/operation counts for the three tiers. Counts are conservative reservations, not a provider billing meter or proof of free eligibility.

## Consumers and authorization gates

The API trace-repository wrapper queues only captured **actual-build** manifests in a four-slot, single-writer advisory queue. It never reconstructs a build from current state and does not put object IO on the inference critical path. Finance/Health and sensitive/restricted verbose observations are disabled. Provider-derived trace bodies are also gated until Phase 14/15 supply durable source/grant references; the existing compact inspector keeps its previous behavior. This deliberate gate does not claim those prerequisite phases are complete.

Evaluation CLIs keep their stdout reports and optionally retain one compressed JSONL batch through the shared tier. Retention needs exactly one canonical active owner; a development `local` identity is not silently assigned to live evaluation data. Privacy-unsafe reports fail advisory retention. `retain_routing_trace` and `retain_debug_replay` expose the shared consumer seam for later orchestration. Current workflows do not select providers, so no new routing orchestrator or canonical routing-decision product is introduced. Supporting artifacts cannot replace authoritative replay facts, reservations or required decision writes.

Grant dependencies are checked through a trusted current resolver on every write/read/reconciliation. The default resolver denies nonempty dependencies: no runtime grant repository is invented. A caller retaining research-derived debug observations must provide verified source rights and their expiry. Export references propagate the union of retained object dependencies and the earliest dependency expiry. The unresolved Phase 15 history/derived-source revocation acceptance remains open; storage contracts do not establish it.

When `ARTIFACTS_ENABLED=true`, account export freezes its declared bounded Postgres/DynamoDB snapshot together with exact generations and live artifact bodies, then returns the ready frozen envelope. Previous export bodies, expired and deleted bodies are explicitly excluded to prevent recursive archives; their metadata remains in snapshot coverage. Required incomplete, oversized, unavailable or corrupt artifacts return **503 `export_artifact_unavailable`** rather than partial success; existing database-export size overflow remains **413**. Retries of a ready export identity return the original frozen snapshot. Export preparation checks aggregate size before fetching bodies. With artifact storage disabled, export returns the ordinary database snapshot only when it contains no live artifact bodies; otherwise it returns **503** rather than silently omitting them. Maintenance continues expiry, revocation and deletion cleanup with new writes disabled. No globally atomic Postgres/DynamoDB/GCS snapshot is promised.

Deletion confirmation writes an owner-wide fence in the lifecycle transaction. Verified API requests are denied except deletion control paths; provider reservations recheck the fence before every send; worker jobs check it before claiming; active-owner scheduling excludes fenced owners. Artifact reads/writes/publication also recheck it. Cancellation can remove that request's fence before irreversible artifact cleanup; after cleanup starts it returns a lifecycle conflict. Existing full physical deletion/recovery gaps remain Phase 9 gates. Local development identity and offline fakes do not establish deployed security acceptance.

`GET /v1/artifacts/{id}` uses the verified owner/application/workspace envelope and returns only available authorized JSON with `Cache-Control: no-store`. It is default off. Browser access uses the default-off `/api/artifacts/{id}` Next.js proxy. There are no signed/public bucket URLs or client upload/key APIs.

## Configuration and cloud acceptance

Apply migration 019 before using the new runtime, including provider/account fencing. `ARTIFACTS_ENABLED=false` is the default and disables new artifact writes and retrieval API access; scheduled maintenance still owns cleanup of existing references. `ARTIFACT_STORE=memory` is local/test only. GCS additionally requires `ARTIFACT_GCS_BUCKET`, an eligible regional `ARTIFACT_GCS_REGION`, `ARTIFACT_GCS_PREFLIGHT_VERIFIED=true`, and a bounded `ARTIFACT_GCS_PREFLIGHT_REFERENCE`. Changing the configured store while live references or recent tombstones name another store fails maintenance until the original configuration is restored and drained. Frontend `ARTIFACTS_ENABLED` enables the authenticated proxy independently. Example files leave both gates off.

Conservative hard upper limits are 1,000 reserved operations/day, **4,000 total/month**, 16 MiB reserved body IO/day, **64 MiB/month**, 64 MiB live compressed stock and 10,000 live references. Operators can reduce daily/stock ceilings, not increase them. Failed/uncertain sends are not refunded. Bounded metadata responses add wire overhead; these are application guardrails, not account-wide free-tier accounting. Tiny observations use evaluation/debug JSONL batches, not one object per event.

Before cloud enablement, verify actual account-wide free eligibility and other workloads, regional STANDARD storage, effective/inherited IAM, private service access and provider/source rights. The adapter checks enforced public access prevention, uniform bucket access, the configured eligible region, STANDARD class, disabled versioning and an explicit zero soft-delete duration; retention locks, requester-pays and managed encryption configuration are rejected. Verify lifecycle/backup/index/container-image costs separately. Grant the service only the required private object and bucket-metadata permissions; never grant public principals or client arbitrary object access. No cloud resource was created or deployed during implementation.

GCS protocol references: [object insertion and generation preconditions](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/insert), [public access prevention](https://docs.cloud.google.com/storage/docs/public-access-prevention), [soft delete](https://docs.cloud.google.com/storage/docs/soft-delete). Protocol fakes are not IAM, billing or cloud acceptance evidence.
