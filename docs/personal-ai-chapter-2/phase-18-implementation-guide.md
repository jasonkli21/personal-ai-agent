# Phase 18 — static endpoint catalog and admission

See the [Phase 18–21 refactor plan](phase-18-21-architecture-refactor-implementation-plan.md) and [refactor results](phase-18-21-architecture-refactor-results.md) for the active boundary and verification. Original phase evidence remains historical.

`EndpointProfile` is the immutable definition of a callable provider/model/deployment/account/credential/cost combination. It contains symbolic credential references, static billing/free-tier and data-use attestations, capabilities, request bounds, exact counter/serializer/schema compatibility and static operation-specific quota bindings. Strict-free automatic admission excludes paid/BYOK/subscription, unknown cost, unverified tier/paid overflow, denied privacy, missing capability/bounds/counter and unknown/ambiguous quota topology before scoring. Time-bounded free attestations expire inclusively.

Static `QuotaBucket` contains authority/unit/window/operation metadata, optional configured ceiling and provenance. It rejects live remaining/reset/observation/freshness fields. P19 alone interprets effective runtime capacity, reservations and health; its `QuotaObservation` extends static topology. Unknown capacity never certifies free eligibility or available capacity.

`EndpointRegistry.candidates` returns every configured profile and rejection, without scores, under a 32-profile/128-KiB registry bound. Configuration reconciliation and CAS snapshot publication advance versions when facts change. Version high-water marks prevent reuse after removal. Immutable `endpoint_profile_definitions` retains exact historical definitions for audit independently of the active set and stores an independent `definition_schema_version`. Version 1 decodes the pre-V2 static profile shape; version 2 decodes the current static shape without validating historical records through the active `EndpointProfile` model. Each decoder emits canonical JSON: set-like capabilities and schema IDs are sorted, quota buckets are ordered by bucket ID, and bucket operations and counter schema IDs are sorted. V1 dynamic quota fields are removed before canonicalization. Unknown schema versions and corrupt definitions fail explicitly; a corrupt definition encountered during registry persistence becomes `RegistryConflictError("immutable_endpoint_definition_conflict")`. A future profile-contract change must add a new definition schema/decoder rather than reinterpret old rows. Migration 022 seeds available old definitions and advances schema/profile identities; it does not invent missing historical configurations.

`revalidate_selected(EndpointRef, requirements, connection=...)` checks the exact current selected version and static admission, optionally holding the registry shared lock in the dispatch transaction. Global registry identity is audit metadata; changes to unrelated profiles do not invalidate selection. Routing reloads requirements from its canonical decision. The old whole-candidate-set revalidation surface is removed.

Configured initial profiles remain Gemini generation/embedding, Groq, Cloudflare and search as applicable. Unverified facts default off/unknown. No provider-name ordering exists in admission. Request workflows remain Gemini-only pending Phase 15 and provider/account acceptance; Groq/Cloudflare lack authoritative counters for count-required tasks.
