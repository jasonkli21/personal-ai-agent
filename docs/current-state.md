# Current implementation state

Updated: 2026-10-07. This is the single living status snapshot. Code, tests, and dated evidence remain authoritative for delivered behavior.

## Implemented boundary

The repository contains a Next.js frontend and FastAPI API/worker. Chat, token-budgeted context assembly, typed context-source/provider admission, Phase 12 model-input building, Phase 13 deterministic context planning, and the Phase 14 bounded actual-build inspector subset are implemented locally, alongside an owner-managed AI profile with explicit per-field sharing, gated memory and lifecycle, bounded research, evidence-backed decisions, travel/shopping modules, application manifests, and partial authentication/account safeguards. Phase 12 combines the active conversation branch, compatible working summaries, eligible memory, and typed provider items under global and per-source ceilings. Phase 13 applies versioned bounded-intent rules before retrieval, selects only registered provider operations and fields, and enforces per-operation allocations under per-source and global ceilings. Required rules reserve budget before optional rules. Default rules retrieve memory only for positive personal-recall questions and select only explicitly shared profile fields; the profile adapter fetches one result per selected field. The offline planner baseline checks planned, retrieved, and injected support through the built-in memory/profile adapters and synthetic Travel, Shopping, Finance, and Health providers. Its byte-based counter is a fixture estimate, not live token-count evidence. The development inspector shows a retained actual chat-build trace when available and always labels the current reconstruction as estimated. Actual traces contain bounded metadata only, retain at most 32 records per conversation, and hash provider-supplied source/item IDs. Phase 14 acceptance remains incomplete because traces do not yet reference immutable Postgres policy/source versions. Experimental product gates remain off by default. See the [root README](../README.md) for current runtime and setup details.

## Persistence

P10.6 switched normal API and worker wiring to Postgres/pgvector plus DynamoDB and removed Firestore SDK, repositories, migration tooling, and runtime fallback. Local/test configurations require explicit Postgres and DynamoDB Local endpoints; deployed configuration targets Neon and federated AWS DynamoDB. This is an implemented code/runtime cutover, not evidence of a live cloud cutover or data migration. The user-reported no-source disposition has not been checked against a cloud account.

## Security and release readiness

Google OIDC, owner mapping, private service invocation, request safeguards, and account workflows are implemented in part. The fixed `local` owner remains a development identity. Staging/production identity, IAM, provider data rights, target-store behavior, and recovery have not received full acceptance. Physical account deletion, deletion-aware restore, full legacy-owner migration, complete provider usage accounting, and operational release gates remain open.

## Planned work and external gates

Chapter 2 Phases 0–2 are completed history; Phase 10 persistence, Phase 11 context-source/provider work, Phase 12 context building, and Phase 13 deterministic planning are implemented locally. Phase 14 provenance/context inspection is partially implemented. It persists bounded chat-build manifests during preparation and connects request IDs through the development inspector proxy, but it does not yet reference immutable Postgres policy/source versions as required by the Phase 10 storage contract. No new registry product was added because the same contract says to preserve code-defined manifests and not add a registry product now; resolving the version-reference design is a local prerequisite to Phase 14 acceptance. The trace records code-defined planner/policy version labels and source-version labels supplied by current providers; it does not store policy bodies, prompts, or provider values. Standalone research/proposal/booking manifests remain the Phase 12 in-memory preparation reports and are not retained by the conversation trace repository. The inspector reports a missing or unsupported historical schema explicitly and never reconstructs an actual build from current state. Its domain baseline and trace tests use synthetic providers; real Travel, Shopping, Finance, and Health providers and app-specific production rules remain future work. Phase 10/11 release acceptance still needs Docker-backed local Postgres/DynamoDB contract checks, live Neon/AWS/GCP verification, and strict-$0 eligibility evidence. The Phase 11 migration and profile repository contract suite are present but opt-in; they still need execution against local Postgres, plus cloud review. Phase 12 provider-count accuracy and live source integrations remain unverified; offline source/count fakes establish only the documented local contracts. Phase 14 still needs immutable Postgres policy/source references, execution against DynamoDB Local, and review of live IAM, retention, export, and deployed development-gate behavior. If a Firestore source is discovered, the reported no-source disposition must be revisited before data is abandoned or deleted.
