# Current implementation state

Updated: 2026-10-08. This is the single living status snapshot. Code, tests, and dated evidence remain authoritative for delivered behavior.

## Implemented boundary

The repository contains a Next.js frontend and FastAPI API/worker. Chat, token-budgeted context assembly, typed context-source/provider admission, Phase 12 model-input building, Phase 13 deterministic context planning, the Phase 14 bounded actual-build inspector subset, and the Phase 15 local permission/sensitivity policy subset are implemented locally, alongside an owner-managed AI profile with explicit per-field sharing, gated memory and lifecycle, bounded research, evidence-backed decisions, travel/shopping modules, application manifests, and partial authentication/account safeguards. Phase 12 combines the active conversation branch, compatible working summaries, eligible memory, and typed provider items under global and per-source ceilings. Phase 13 applies versioned bounded-intent rules before retrieval, selects only registered provider operations and fields, and enforces per-operation allocations under per-source and global ceilings. Required rules reserve budget before optional rules. Default rules retrieve memory only for positive personal-recall questions and select only explicitly shared profile fields; the profile adapter fetches one result per selected field. The offline planner baseline checks planned, retrieved, and injected support through the built-in memory/profile adapters and synthetic Travel, Shopping, Finance, and Health providers. Its byte-based counter is a fixture estimate, not live token-count evidence. Phase 15 adds typed server-owned provider/operation/field policy, deny-by-default cross-app checks, exact returned-payload projection checks, mandatory-history authorization before summaries/counting, and pre-disclosure policy checks for research, itinerary proposals, and booking extraction. Authorized generation paths carry the final sensitivity and policy version in an internal inference envelope. Finance and Health declarations restrict selected domain fields without application-name branches. The development inspector shows a retained actual chat-build trace when available and always labels the current reconstruction as estimated. Actual traces contain bounded metadata only, retain at most 32 records per conversation, and hash provider-supplied source/item IDs. Phase 14 remains incomplete because traces do not yet reference immutable Postgres policy/source versions; Phase 15 also remains partial because revocation dependencies are not yet carried end-to-end through conversation history, summaries, memory, and derived artifacts. Experimental product gates remain off by default. See the [root README](../README.md) for current runtime and setup details.

Gemini generation and summary calls reject missing or invalid inference envelopes before dispatch. The built-in fake inference client explicitly permits unscoped development/test calls. A request's application label selects a registered namespace but does not independently prove principal membership; live domain sources must wait for an authoritative membership check.

Phase 16 adds provider-neutral streaming, bounded and structured generation, token-count, usage, capability, and embedding-space contracts. Chat consumes explicit terminal events; summaries and memory extraction use neutral completion operations; and vectors carry a versioned provider/model/dimensions/normalization/task identity. The nine local findings in the 2026-10-07 independent review are addressed, including memory-disclosure policy propagation, endpoint-bound authoritative counts, exact structured-request counting, stream teardown/protocol checks, synchronous deadlines, lifecycle embedding-space identity, and non-chat invocation attribution. Gemini remains the only configured provider, and live compatibility checks are opt-in. No embedding re-index migration occurred.

Phase 17 adds neutral-contract reference adapters for Groq and Cloudflare Workers AI with bounded/streamed generation, model-gated structured output, normalized errors, terminal status, usage, and safe rate-limit metadata. Their configuration gates default off and require explicit account/model free-tier and privacy attestations plus a preflight reference before live calls; privacy approval now carries a configured effective-sensitivity ceiling, and returned model identities must match the configured model or an exact preflight-approved alias. Completion/stream bodies and SSE lines/events have fixed byte limits, and empty/whitespace terminal output is incomplete. Structured output requires a separate model compatibility attestation. Both adapters use deterministic HTTPX transports in offline contract checks. They do not implement authoritative token counting or embeddings, so current application workflows remain wired to Gemini and will not dispatch to these adapters. No account/tier/privacy, live-provider, or paid-path checks were performed.

Phase 17R adopts pinned LiteLLM 1.102.1 as the transport layer for Gemini, Groq, and Cloudflare Workers AI behind the Personal AI inference gateway. LiteLLM types stay inside that gateway; endpoint/model/credentials remain explicit per call; Router, Proxy, cross-provider fallback, and SDK/HTTP retries are disabled. Gemini's countTokens shim uses the pinned Gemini request transform to count the same system instructions and structured schema that generation serializes. The Gemini missing-usage field, Groq `service_tier` field, and Cloudflare per-call HTTP handler are narrow SDK-gap shims, covered by intercepted request tests. Current application workflows remain Gemini-only because Groq and Cloudflare still lack authoritative same-endpoint counters. No live provider, privacy, account/tier, or paid-path check was performed; see [Phase 17R evidence](personal-ai-chapter-2/phase-17r-implementation-evidence.md).

## Persistence

P10.6 switched normal API and worker wiring to Postgres/pgvector plus DynamoDB and removed Firestore SDK, repositories, migration tooling, and runtime fallback. Local/test configurations require explicit Postgres and DynamoDB Local endpoints; deployed configuration targets Neon and federated AWS DynamoDB. This is an implemented code/runtime cutover, not evidence of a live cloud cutover or data migration. The user-reported no-source disposition has not been checked against a cloud account.

## Security and release readiness

Google OIDC, owner mapping, private service invocation, request safeguards, and account workflows are implemented in part. The fixed `local` owner remains a development identity. Staging/production identity, IAM, provider data rights, target-store behavior, and recovery have not received full acceptance. Physical account deletion, deletion-aware restore, full legacy-owner migration, complete provider usage accounting, and operational release gates remain open.

## Planned work and external gates

Chapter 2 Phases 0–2 are completed history; Phase 10 persistence, Phase 11 context-source/provider work, Phase 12 context building, Phase 13 deterministic planning, Phase 16 provider-neutral inference/embedding contracts, Phase 17 Groq/Cloudflare reference generation adapters, and Phase 17R LiteLLM transport migration are implemented locally. Phase 14 provenance/context inspection is partially implemented. It persists bounded chat-build manifests during preparation and connects request IDs through the development inspector proxy, but it does not yet reference immutable Postgres policy/source versions as required by the Phase 10 storage contract. No new registry product was added because the same contract says to preserve code-defined manifests and not add a registry product now; resolving the version-reference design is a local prerequisite to Phase 14 acceptance. The trace records code-defined planner/policy version labels and source-version labels supplied by current providers; it does not store policy bodies, prompts, or provider values. Standalone research/proposal/booking manifests remain the Phase 12 in-memory preparation reports and are not retained by the conversation trace repository. The inspector reports a missing or unsupported historical schema explicitly and never reconstructs an actual build from current state. Its domain baseline and trace tests use synthetic providers; real Travel, Shopping, Finance, and Health providers and app-specific production rules remain future work. Phase 15 permission/sensitivity policy is partially implemented. Server-owned application declarations cover provider operations and fields; unknown, cross-app, and unselected returned payload disclosure fail closed. Chat baseline history is authorized before summary reads/refresh and counting, while standard and iterative research, itinerary proposals, and booking extraction preflight their application/provider/field rules before repository, source, counter, or model work. The internal inference client receives the final effective sensitivity and policy version for authorized generation. The implemented policy versions remain code labels rather than immutable Postgres records. Existing profile/memory item dependencies are rechecked before injection, but source-derived chat history and summaries do not yet carry revocable source dependencies end-to-end through later turns, traces, exports, and artifacts. Cross-app grants remain disabled and no live domain sources are implemented. Phase 10/11 release acceptance still needs Docker-backed local Postgres/DynamoDB contract checks, live Neon/AWS/GCP verification, and strict-$0 eligibility evidence. The Phase 11 migration and profile repository contract suite are present but opt-in; they still need execution against local Postgres, plus cloud review. Phase 12 provider-count accuracy and live source integrations remain unverified; offline source/count fakes establish only the documented local contracts. Phase 14 still needs immutable Postgres policy/source references, execution against DynamoDB Local, and review of live IAM, retention, export, and deployed development-gate behavior. Phase 15 still needs end-to-end revocation coverage and external review of provider data-use/retention and domain membership. Phase 16's nine local review findings are resolved and covered by offline checks; live Gemini count, structured-output, streaming, and embedding compatibility remains unverified. Phase 17 adapter conformance is locally implemented, but both new live paths remain disabled and the app continues to use Gemini because the alternate adapters have no same-endpoint authoritative counters. Account/model eligibility, privacy suitability, live compatibility, and Cloudflare strict-free model access remain unverified. If a Firestore source is discovered, the reported no-source disposition must be revisited before data is abandoned or deleted.
