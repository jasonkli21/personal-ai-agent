## Scope-preserving corrections and known risks

1. Phase 0's generated backlog mixed audit tasks with contracts, fakes, security policy, storage design, integration tests, and phase implementation boilerplate. Its [revised plan](plans/phase-0-implementation-plan.md) limits Phase 0 to review and documentation. Those substantive commitments remain in their later phases.
2. `DomainModule` currently registers Travel/Shopping comparison behavior. Phase 2 must add application definitions by extending/reusing the registry seam, while Phase 3 adds typed context-provider contracts. No existing domain app database integration is implied by the current `domains/` package.
3. The stream-only `LLMClient` and optional `stream_bounded` convention need Phase 8 reconciliation before adding providers/routing. Gemini structured extraction is provider-specific; itinerary/booking JSON validation is service-specific. Keep model calls through the shared context budget.
4. Current provider budgets are conservative HTTP estimates and Phase 8 research ledgers are per-run estimates. Phase 11 must account for counting, summaries, embedding, worker, search and generation operations before strict-$0 routing can rely on capacity. Phase 9's open accounting acceptance is not automatically closed by a new ledger plan.
5. Firestore vector indexes are dimension/model dependent; Phase 12 GCS is additive to Firestore. Existing deployment provisions selected operational indexes but not every optional vector index, artifact bucket, billing cap, or verified recovery process.
6. Phase 17.1 depends on current external ChatGPT plan eligibility/API/bridge rules. Re-verify at implementation and release; if unavailable, mark the additive lane and its downstream sidecar tasks pending, without removing the underlying strict-free or domain requirements. Reordering baseline domain work around that blocker would require an explicit scheduling decision. The bridge must keep reusable credentials out of managed cloud and browser storage. Phase 17.2 keeps ChatGPT out of automatic strict-free routing; Phase 17.3 reuses the context builder; Phase 17.4 supplies a shared domain contract.
7. Travel/Shopping current code lacks authoritative trip/project state. Finance/Health have no local modules. Phases 18–23 require domain-owned read and mutation boundaries; core must not query domain databases directly or treat AI output as a write.
8. Existing Phase 9 deletion, owner migration, provider-data review, cloud IAM, backup/restore, and operational release gates remain independent blockers for live private-data use. Offline Phase 1 work can start with synthetic data and default-off gates.
9. The generated Phase 23 plan qualified confirmation as only needed where domain rules require it. Its wording now follows the integrated roadmap: an AI-assisted authoritative write requires user confirmation as well as target-domain validation and authorization.
